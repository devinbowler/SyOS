# SyOS Build Plan — Implementation Brief for Claude Code

*Companion to `syos-design-doc.md` (v0.3). The design doc is the source of truth for **what and why**; this file is the working brief for **how**. If the two conflict, the design doc wins — flag the conflict instead of silently choosing.*

**Suggested use:** put both files in the repo root (or `docs/`) and add a `CLAUDE.md` that says: *"Read docs/syos-design-doc.md and docs/syos-build-plan.md before any work. Follow the build plan's phase order and conventions."*

---

## 0. Ground rules for the implementing agent

1. **Target:** Debian 13 (trixie) stable, amd64, minimal netinstall baseline (standard utilities + SSH only). Assume nothing else is installed.
2. **Phase order is strict.** Do not start Phase N+1 until Phase N's acceptance criteria pass. Each phase must leave the system daily-drivable.
3. **Idempotency is non-negotiable.** `./bootstrap.sh` run twice on the same machine must be a no-op the second time (safe to rerun after any partial failure). Every change it makes must be re-runnable.
4. **No configuration outside the repo** except `~/.config/syos/local.conf` (per-machine, generated by bootstrap's interactive prompt, gitignored pattern documented).
5. **Plain, boring tech.** Bash for bootstrap and small glue, Python 3 (stdlib-first) for `syos-focusd` and the `syos` CLI. No frameworks unless a task below names one. Shell scripts pass `shellcheck`; Python passes `ruff` defaults.
6. **Mouse-first constraint:** no SyOS feature may *require* a keyboard shortcut. Sway defaults may exist but nothing in docs or UI depends on them.
7. **Root/user boundary:** only `syos-focusd`, its `profiles.conf`, and its systemd unit are root-owned. Everything else is user-space. The user CLI talks to the daemon over a Unix socket with a strict allow-listed command set.
8. **VM-aware:** bootstrap must detect virtualization (`systemd-detect-virt`) and apply `WLR_NO_HARDWARE_CURSORS=1` + a safe output fallback so the whole system is testable in VirtualBox per design doc §8.
9. **Every phase ends with:** updated `docs/`, a `syos doctor` check covering the new surface area, and a snapshot-tested clean-VM bootstrap run.
10. **Honesty rule:** if a design-doc assumption turns out wrong on real Debian 13 (package missing, flag renamed), fix it, note it in `docs/decisions.md`, and keep moving. Do not fake acceptance criteria.

## 1. Repository conventions

```
syos/
├── CLAUDE.md               # agent entry point → points at docs/
├── bootstrap.sh
├── packages.list           # one apt package per line, comments allowed
├── packages-flatpak.list
├── stow/                   # `stow -t $HOME <dir>` layout, one dir per app
│   ├── sway/.config/sway/config
│   ├── foot/.config/foot/foot.ini
│   ├── fuzzel/  waybar/  nvim/  calcurse/  yazi/  btop/
│   └── syos/.local/bin/…   # syos CLI + helper scripts
├── theme/
│   ├── palette.conf        # KEY=value; single source of truth
│   └── generate.sh         # emits themed config fragments into stow/
├── focusd/
│   ├── syos-focusd         # python3, installed to /usr/local/sbin
│   ├── syos                # python3 user CLI, /usr/local/bin
│   ├── profiles.conf       # installed root-owned to /etc/syos/
│   └── syos-focusd.service
├── iso/                    # empty until Phase 4
└── docs/
    ├── syos-design-doc.md
    ├── syos-build-plan.md  # this file
    ├── decisions.md        # running log of deviations/decisions
    └── testing.md          # how to run the VM test loop
```

- Theme generation is build-time: `generate.sh` writes fragments *into* `stow/` before stowing, so stow remains the only deploy mechanism.
- All syos scripts prefixed `syos-` and reachable via the `syos` CLI subcommand pattern (`syos focus…`, `syos dev…`, `syos doctor`).

## 2. Phase 0 — Skeleton

**Goal:** fresh Debian VM → clone → `./bootstrap.sh` → reboot → land in a themed Sway session with foot and Chrome running as tabs.

Tasks:
- [ ] Repo scaffold per §1, with CLAUDE.md, docs, empty stubs where needed.
- [ ] `packages.list` v1: sway, swaybg, xwayland, foot, waybar, fuzzel, stow, git, curl, fonts-* (Iosevka via ttf download step if not packaged — check trixie first), pipewire, wireplumber, xdg-desktop-portal-wlr, policykit agent, brightnessctl, pavucontrol, network-manager.
- [ ] `bootstrap.sh`: apt update/install from manifest → add Google Chrome apt repo + install → run `theme/generate.sh` → stow all dirs → first-run prompt writing `local.conf` (detected outputs via `swaymsg -t get_outputs` fallback text entry; scale; font size) → install greetd or configure autologin-to-sway (pick greetd + tuigreet; document) → enable services → detect VM and write VM env fragment → print summary → offer reboot.
- [ ] Minimal Sway config: tabbed default layout (`workspace_layout tabbed`), no titlebar decorations beyond tab labels, 1px borders, zero gaps, palette applied, outputs from `local.conf` include.
- [ ] `theme/palette.conf` + `generate.sh` emitting foot + sway + waybar CSS fragments.
- [ ] Minimal Waybar: workspaces, clock, network, battery — clickable workspaces confirmed.
- [ ] `docs/testing.md`: the VirtualBox loop (snapshot "fresh-debian" → clone → bootstrap → verify → restore).

**Acceptance:** clean VM run lands in Sway; opening Chrome from a foot shell produces a *tab* next to foot, both themed; second `bootstrap.sh` run makes no changes; `shellcheck` clean.

## 3. Phase 1 — The Panel (mouse-first)

**Goal:** a full mouse-only workday inside SyOS.

Tasks:
- [ ] Full Sway config: 5 named workspaces (Work/Web/Comms/Ops/Board), app `assign` rules (Chrome→Web, VSCode→Work, zoom/slack→Comms), floating whitelist (file pickers, auth dialogs) with fixed geometry, drag-tabs verified.
- [ ] Waybar cockpit per design §4.2:
  - launcher button → fuzzel
  - window-control cluster: close / split-h / split-v / move-to-workspace (custom modules calling `swaymsg`; move-to-workspace opens a tiny fuzzel-dmenu picker)
  - tool buttons: calendar (calcurse), notes (nvim notes), terminal (foot), files (yazi), downloads (aria2 TUI), monitor (btop) — each button = "focus existing or spawn in home workspace" via a `syos-summon <name>` helper using `swaymsg` marks
  - center: next-event module reading calcurse (`calcurse -n`), click → Board workspace
- [ ] Built-ins installed + themed: calcurse, yazi, btop, nvim (with a minimal notes setup: daily note command, fuzzy search via telescope or fzf-lua), aria2 + a TUI/status view.
- [ ] Theming pass: GTK dark (adw-gtk3 or equivalent), Chrome forced dark + compact via managed flags/policy, fuzzel/waybar/btop/calcurse all emitting from `palette.conf`.
- [ ] VSCode installed (Microsoft apt repo), assigned to Work, dark themed.
- [ ] Screen-share verification procedure in `docs/testing.md` (Chrome → meet test page → confirm portal picker appears). Mark VM-only limitations.
- [ ] `syos doctor` v1: stow symlink integrity, package drift vs manifest, failed systemd units, portal presence.

**Acceptance:** with keyboard unplugged (or unused), a user can: switch workspaces, open every built-in from the bar, close/split/move windows from the bar, launch any app from fuzzel, see next calendar event on the bar. All visuals match palette. `syos doctor` passes.

## 4. Phase 2 — Enforcement + Dev

**Goal:** the three focus levels genuinely enforce; the dev-container flow runs a real project.

Tasks — `syos-focusd`:
- [ ] Daemon skeleton: python3, systemd unit (`Restart=always`, hardening: `ProtectSystem=strict` with needed paths, `NoNewPrivileges` off only if required for nftables), Unix socket at `/run/syos/focusd.sock` (0660, group `syos`).
- [ ] Command set: `start <level> <minutes>` (refuse if session active at higher level), `status` (level, remaining), `extend <minutes>`. **No stop.** Attempted `systemctl stop` during a session: unit uses `ExecStop` guard script that exits nonzero while session active + `Restart=always`; document residual escape (reboot) honestly in docs.
- [ ] Sessions do NOT persist across reboot (state in `/run`).
- [ ] Level 1: `/etc/hosts` sinkhole block (managed markers), nftables table `syos` with domain-resolved IP sets refreshed periodically, DNS pinning: install/configure a local resolver (systemd-resolved with DNS forced, or dnsmasq) and nftables redirect of all port-53/DoT egress to it; blocklists: static list (x.com, instagram.com, facebook.com, youtube.com, twitch.tv + known CDN/API domains) + StevenBlack porn hosts list with weekly systemd-timer refresh and local cache (must work offline from cache).
- [ ] Level 2: adds AI domain list from `profiles.conf` (claude.ai, api.anthropic.com, chatgpt.com, api.openai.com, gemini.google.com, api.githubcopilot.com, copilot-proxy.githubusercontent.com, cursor domains, codeium/windsurf, perplexity.ai — verify current endpoints at build time and record in decisions.md). Editor gate: `syos focus status --json` consumed by an nvim init hook (skip loading AI plugins when level ≥ 2) and a VSCode wrapper that launches with Copilot-disabling settings overlay.
- [ ] Level 3: adds Chrome kill: launch wrapper (`google-chrome` shadowed earlier in PATH → asks focusd, refuses at L3), watchdog loop kills chrome/chromium processes, `chmod o-x`-style per-user execute denial via ACL (`setfacl -m u:$USER:r--` on the binary) for session duration, restored on expiry.
- [ ] `profiles.conf` root-owned 0600; daemon refuses `start` if file was modified in the last N minutes *while a session was pending* is NOT required — simply: file only editable via sudo, and daemon re-reads at session start only.
- [ ] Bar integration: focus module (level + countdown, accent green/amber/red via waybar class), click → menu (fuzzel-dmenu): level → duration presets (25/50/90/custom) → confirm step.
- [ ] Downloads: aria2 daemon (user service) + `syos dl add` (from clipboard via wl-paste) + bar button opens queue TUI.
- [ ] `syos dev <path>`: checks devcontainer CLI + docker present (add to manifest: docker.io or docker-ce — decide and record), `devcontainer up`, opens foot tab running `devcontainer exec` shell with nvim config mounted (bind mount of `~/.config/nvim` unless project forbids), prints forwarded ports from devcontainer.json common fields.
- [ ] `syos doctor` v2: focusd health, socket perms, resolver pinning active-check, blocklist cache age.

**Acceptance (run in VM):** start L1 → x.com and youtube.com fail in Chrome including after switching Chrome's DNS-over-HTTPS setting; start L2 → claude.ai fails AND nvim starts without AI plugins; start L3 → Chrome will not launch by any normal means and running instances die within 5s; `syos focus stop` does not exist; `systemctl stop syos-focusd` fails mid-session; reboot clears everything. `syos dev` brings up a sample devcontainer project and `moon --version` (or a stub task) runs inside it.

## 5. Phase 3 — Make it yours

- [ ] Custom scheduler TUI (Python + Textual): day agenda + week view, timeboxing, todo, and "start focus session from event" action; reads/writes calcurse data format so calcurse remains the storage + a fallback UI. Replaces calcurse as the `Mod`-less calendar button target.
- [ ] Calendar-triggered focus: focusd timer scans upcoming events for `[focus:<level>]` tags and auto-starts sessions (with a 2-minute bar warning beforehand).
- [ ] Ops dashboard: one Board/Ops layout preset (btop + downloads + doctor summary) restorable by a bar click (swaymsg layout script).
- [ ] Borg nightly backup: user timer, target from `local.conf`, `syos doctor` checks last-success age.

**Acceptance:** a `[focus:2]` calendar event fires enforcement on time; scheduler TUI creates/edits events that calcurse can read; backup runs and doctor reports it.

## 6. Phase 4 — Portability

- [ ] Debian preseed file automating the minimal install + late_command that clones the repo and drops a firstboot service running `bootstrap.sh --noninteractive` (scaling prompt deferred to first login).
- [ ] `iso/build.sh`: remaster official netinstall ISO with the preseed (document tooling: xorriso). Output: `syos-install.iso`.
- [ ] Fleet polish: `local.conf` profiles for the Zenbook and Panasonic committed as *examples* (`local.conf.zenbook.example` etc.) once real values are known.
- [ ] Full metal test checklist in `docs/testing.md` (scaling, suspend, webcam/mic screen share).

**Acceptance:** USB from the ISO installs to a VM unattended and boots into SyOS with only the scaling prompt at first login.

## 7. Phase 5 (deferred) — Keybind layer

Out of scope until the user asks. Constraint to preserve until then: nothing added in Phases 0–4 may make a keyboard shortcut the only path to any action.

## 8. Testing procedure (summary — full version lives in docs/testing.md)

1. VirtualBox VM "syos-test": Debian 13 netinstall, minimal, snapshot `fresh-debian` taken immediately after first boot.
2. Every phase: restore snapshot → clone repo at HEAD → `./bootstrap.sh` → run that phase's acceptance list → run it *again* to prove idempotency.
3. Enforcement tests (Phase 2) run entirely in-VM; network blocking is verifiable there.
4. Real-hardware items (HiDPI scale, suspend, camera) are tracked as a separate checklist and only block Phase 1/4 sign-off on metal, never VM iteration.

## 9. Known open items for the agent to resolve (and log in decisions.md)

- Iosevka packaging on trixie (package vs vendored TTF download in bootstrap).
- greetd/tuigreet availability on stable vs backports; fallback = agetty autologin + `exec sway` guard in profile.
- docker.io (Debian) vs docker-ce (upstream) for the devcontainer CLI.
- devcontainer CLI install method (npm global vs distributed binary).
- Exact current AI-endpoint domain lists at build time.
- Whether `ExecStop` guard + `Restart=always` sufficiently resists `systemctl stop`; if not, add a systemd drop-in with `RefuseManualStop=yes` toggled per-session and document behavior.
